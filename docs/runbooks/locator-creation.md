# Runbook: Locator Authoring & XPath Guide

## Purpose
Guidelines for QA engineers to construct reliable, resilient XPaths and templates for MIS web forms.

## 1. XPath Best Practices for Complex Forms
- **Prefer stable attributes:** Use `@data-test`, `@name`, `@id` (if not autogenerated/dynamic).
  - Example: `//input[@data-test='phone-input']`
- **Use label relationships:** Target inputs via associated labels or fieldset legends.
  - Example: `//input[following-sibling::label[text()=' Населенный пункт ']]`
  - Example: `//fieldset[descendant::h3[text() = ' Адрес проживания ']]//input[following-sibling::label[text()=' Улица ']]`
- **Use partial matching carefully:**
  - `contains(@id, 'lastName')` or `starts-with(@id, 'series_document')`.

## 2. Testing XPath in Browser Console
Before saving into Mistension, test your XPath in Chrome DevTools Console:
```javascript
$x("//input[contains(@id, 'lastName')]")[0]
```
Verify that it returns exactly the desired `<input>` element.

## 3. Selecting Template Format
- **Russian SNILS:** `%snils`
- **Date:** `%date`
- **Phone number:** `+7 911 %d3-%d2-%d2`
- **Passport:** Series `%d4`, Number `%d6`
- **Email:** `%s7@%s5.com`
- **Static values:** `г. Санкт-Петербург`, `пр-кт Металлистов`
